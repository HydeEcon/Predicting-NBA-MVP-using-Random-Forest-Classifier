# Predicting-NBA-MVP-using-Random-Forest-Classifier
This repository uses a Random Forest Classifier, and data scraped from Basketball Reference, to determine who will win and not win the NBA MVP award.

# Data Collection

First, we need to actually get the data.  To do this, we code a webscraper that pulls all player statistics, both basic and advanced, from Basketball Reference.  It collects all data from the 1980 season to the 2026 season.  This collection process might take a while, as it is over 700,000 entries worth of data.  Withing our webscraper there is also a line that creates and MVP dummy variable column, as Basketball Reference only has an awards column with that actual names of awards.

# Data Cleaning

After our webscraper is done retrieving our data, it is time to clean it.  To do this we first drop any columns with strings, except for player names, and any rows with NaN, as these won't be useful for the predictive model to train on.  We drop NaN data, instead of turning them into an integer like 0, because NaN means that that particular statistic wasn't recorded for a certain player.  This happens more often with older players, as more advanced statistical measures, such as games started in, weren't recorded back then.  Next we introduce minimum thresholds;  since there is a lot of entries, but not many MVP's, we have a vary unbalanced set of data.  To reduce this imbalance, we introduce a minimum threshold for each major statistical category, such as points, assists, rebounds, etc.  This threshold is set at the minimum any MVP has ever won with said stats.  Meaning if a threshold, such as points, is set at 15.5, that means any player with less than 15.5 points will be removed from our data, as no MVP has ever won with less than 15.5 points (per game). We also exclude any season before 2001, as this was the year zone defense was allowed, a vary major rule change that changed how everyone would play.

# Random Forest Classifier(s)

After this first round of cleaning we are drop from 700,000 entries and 46 MVP winners, to just over 500 entries and 25 MVP winners, making a much more balanced data set.  So we run our first Random Forest Classifier, to determine if additional data preparation is needed.  Which gives us these results:

<img width="497" height="207" alt="RFCResults_1" src="https://github.com/user-attachments/assets/e649f317-ada5-4706-a2e3-82d2dacb0aaa" />

So what does this mean?  Well there's a few measures that we need to care about.  First, 0 and 1 are dummy variables, where 0 means didn't win MVP, and 1 means did when MVP.  Under precession we can see the model was very accurate, 94%, when determining who didn't win MVP, but very inaccurate, at 50%, when predicting who would win MVP.  We also see that under recall, the measure that shows how often our model was able to predict the MVP winner in our data set, there is a 99% accuracy for not winning MVP, and only a 14% accuracy for winning.  This clearly shows that our model is very biased, and simply just predicting everyone won't win MVP, as the majority of people don't.  This is great for predicting who won't win MVP, but that's not what we're going for, we need our "1" dummy variable to have a higher accuracy.  So lets add some hyperparameters and a seasonal loop.

Our seasonal loop basically makes it so our predictive model looks at our data in groups of seasons, rather than all at once.  So for example, if it's trying to predict the 2006 MVP winner, it won't compare data from 2003 against data from 2019.  We also make it so data is trained on previous seasons, rather than future seasons.  This means if our model is predicting the 2010 MVP winner, it will look at data from 2001, then 2002, then 2003, etc, again preventing future data to predict past outcome.  We also include hyperparameters, such as adding n-estimators, a way to prevent overfitting, and a class weight, which prevent the model from just defaulting to 0 like it originally did.  Doing this gives us these results:

As we can see, our model is far more accurate.  The recall rate jumps up from 14% all the way to 42%.  We also see the model has a macro average (combines the accuracy of predicting didn't win MVP and winning MVP), of 69%, a significant improvement from the 57% of our original model. This means our model is no longer just guessing 0 for every player, and actually determining if a player with specific stats will win or not.  While the recall is still under 50%, and there are some improvements that can be made, a predictive model with a ~70% is still both accurate and useful.

# The 2026-2027 Season

So how can we use this model to predict the 2027 season?  Well we first change our end year in the webscraper, and since our model is mostly trained on Per Game statistics, one we remove the Games Played threshold, we don't need to wait to run it at the end of the season to start getting results (although, obviously, end of season stats will be best to use).  We can also drop any totals columns and awards data on our model to better predict the current season.  However, this is just preparation, how do we actually interpret the model for the 2026-2027 season?  Well we know that our current model predicts with a ~70% accuracy, meaning that for any play it predicts winning or not winning the NBA MVP award, it will get right about 70% of the time.  Using this accuracy, we know that if our model predicts a player winning the MVP, there's around a 70% change of it being correct.  It can also predict multiple MVP winners in a single season, meaning there's a tight MVP race going on.  however the model isn't perfect, and there are other things that MVP winners are affected by, such as Team Comp or Voter Fatigue, that our model doesn't take into account.  So it is important to use intuition and other predictive measure, alongside the model, to get the most accurate results.
